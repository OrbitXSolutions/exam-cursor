CHANGES AND RATIONALE

A. Logging and support APIs
Reviewed middleware, migrations/snapshot, enums, UI request/filter/response
contracts, Serilog configuration, service registration and audit usage.
- Restored a mapped SystemLog entity and metadata DTO/service/controller APIs
  for the existing support screens, with bounded page size and SuperAdmin access.
- Added a bounded channel and background database batching with finite timeout,
  backoff and drop reporting. Full queues and failed batches do not block exam
  requests and are not retried indefinitely.
- Removed whole-response MemoryStream capture, request/response body capture,
  raw authentication diagnostics, and historical payload exposure in support
  projections. Large responses no longer incur response-sized logging copies.
- Safe exception diagnostics and generated trace identifiers preserve technical
  support context without storing arbitrary exception messages/payloads.
- Technical files are node/environment identified and asynchronously written
  through a bounded sink. Default legacy dual SQL Serilog sinks are retired;
  business audit records and SystemLogs remain distinct. Old SQL tables are not
  dropped. Runtime log failures are observable through stderr/queue warnings.
- Bounded SystemLogs retention replaces cleanup targeting the retired default
  Serilog sink. OS file retention remains separately configured.
- Frontend diagnostics are metadata-only; proxy URLs omit query parameters.

Logging is best-effort diagnostics, not a lossless audit journal. Queue overload,
process failure or unavailable SQL/disk can lose entries. Existing business
audit records retain their separate semantics. Test evidence must not be read
as proof that every legacy service log statement is safe in every failure.

B. Multi-server state
Reviewed cache consumers, hub registration, limiter ordering, Identity key
handling, background mutation cycles and filesystem read/write/delete paths.
- ICacheService remains compatible with existing consumers, but now always
  misses/executes the authoritative query. No process-local DTO cache/key registry
  remains behind it. No speculative distributed cache invalidation was added.
- Added the supported SignalR Redis backplane when Redis is configured.
  MultiServer startup validation requires it and consistent configured shared
  paths. Redis is not used as a new business-data cache.
- JWT authentication now precedes rate limiting; authenticated users no longer
  share the unauthenticated Host bucket. Anonymous clients use the trusted
  remote IP. Per-node limits remain configurable, not globally distributed.
- Added explicit trusted proxy forwarding, exact configurable CORS origins,
  and optional shared data-protection key-ring/certificate configuration;
  multi-server mode requires the latter to avoid node-local Identity tokens.
- SQL session application locks coordinate background work. Attempt expiry
  changes are made conditionally/transactionally to avoid stale status writes;
  audit work no longer outlives its scoped service through detached Task.Run.
- Shared StoragePaths resolves the same configured roots for serving/upload/
  download/retention and license operations. Relative single-node compatibility
  is retained; shared data migration is an operator procedure, not automatic.
- The public static route no longer exposes video-chunks; existing authorized
  recording APIs must be used. Image upload type validation and controlled
  extensions prevent the confirmed active-document upload path.

Removing caches increases SQL work. This is an intentional correctness-first
trade-off, NOT evidence of unchanged performance. Real two-node SQL/backplane/
storage/network testing and full workload measurement remain required.

C. Configuration and provider diagnostics
Reviewed tracked backend configuration, production defaults, frontend URL usage,
SMTP/SMS/OpenAI diagnostics, notification URL defaults and deployment guidance.
- Removed deployment connection/SMTP values from appsettings; JWT/encryption
  values must be supplied securely, with startup validation rather than fallback
  to known placeholder values. No actual credentials were tested or rotated.
- Added customer examples with documentation-only addresses/blank secrets,
  safe JSON override semantics and explicit multi-server prerequisites.
- Externalized CORS, storage/license roots, proxy trust and provider endpoint
  settings. SMTP sender/vendor and notification external-demo fallbacks are not
  acceptable production defaults. Existing DB provider settings keep precedence.
- SMTP and SMS delivery waits are bounded; diagnostics omit recipient lists and
  raw provider response bodies. AI diagnostics no longer emit model content.
- Frontend normalizes backend API-base/origin configuration and removes the
  build-time network font dependency where supported by the existing system stack.
- No blanket TypeScript casting, unrelated business-rule adjustment or dependency
  upgrade campaign was undertaken to hide pre-existing validation failures.

New production dependencies were selected only for the missing capabilities:
Microsoft.AspNetCore.SignalR.StackExchangeRedis 9.0.20 and
Serilog.Sinks.Async 2.1.0. The advisory tool reported no vulnerabilities for
these requested versions before installation. This is not a complete dependency
vulnerability assessment. Focused test tooling is tracked in the test project.
