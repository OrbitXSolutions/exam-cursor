The batch removal client sends a JSON candidateIds array in a DELETE body. The
backend expects that body. The shared Next.js DELETE proxy forwarded the method
and authentication but omitted the body, so the intended candidate selection
could not reach the controller through the normal application route.

This is transport loss, not a business-rule decision about removing candidates.
The read-only wider result review was also checked against current source;
no speculative scoring or certificate policy change was made.

BOUNDED FIX
Preserve the DELETE request body and incoming content type when forwarding.
Keep bodyless DELETE supported, existing endpoint/query/auth forwarding, API
error envelopes and correlation/license/retry response headers unchanged.
No batch domain-service, validation, candidate assignment rule, schema or
authorization change is needed for this transport correction.
