# SmartExam — On-Premise First Deployment Guide

**Target:** Client Server (On-Premise)  
**System:** SmartExam / Smart_Core  
**Prepared by:** Build4IT

---

## Pre-Deployment Checklist (Before You Go to Client)

- [ ] Build4IT has generated a `license.json` for the client's domain/IP
- [ ] `public.pem` is available (same file used for all clients)
- [ ] Backend build is compiled in Release mode
- [ ] Frontend is built (`npm run build` / `pnpm build`)
- [ ] DB migration scripts are ready
- [ ] Client server has SQL Server installed and accessible
- [ ] Client server has IIS or .NET Hosting Bundle installed (for backend)
- [ ] Client server has Node.js or a static web server (for frontend)

## Step 1 — Prepare the Server

### 1.1 Install Prerequisites

- **SQL Server** (2019 or later recommended)
- **.NET 8 Runtime + ASP.NET Core Hosting Bundle** → [Download](https://dotnet.microsoft.com/en-us/download/dotnet/8.0)
- **IIS** with the ASP.NET Core Module
- **Node.js 20+** (only if serving frontend via Node/Next.js server)
- **URL Rewrite Module** for IIS (if using IIS as reverse proxy)

### 1.2 Create Directory Structure on Server

```
C:\SmartExam\
    Backend\          ← published API files
    Frontend\         ← built Next.js files
```

---

## Step 2 — Configure the Database

### 2.1 Create the Database

In SQL Server Management Studio (SSMS):

```sql
CREATE DATABASE SmartExamDB;
```

### 2.2 Create a SQL Login for the Application

```sql
CREATE LOGIN smartexam_user WITH PASSWORD = 'YourStrongPassword!';
USE SmartExamDB;
CREATE USER smartexam_user FOR LOGIN smartexam_user;
ALTER ROLE db_owner ADD MEMBER smartexam_user;
```

### 2.3 Run EF Core Migrations (Apply Database Schema)

On the server (or from dev machine pointing to client DB):

```bash
cd Backend-API
dotnet ef database update --configuration Release
```

Or run the migration SQL script manually if `dotnet ef` is not available on server.

### 2.4 (If Upgrading from Old Deployment) Run RBAC Migration

If the old database had `SuperDev`, `ProctorReviewer`, or `Auditor` roles, run:

```sql
-- Rename SuperDev → SuperAdmin
UPDATE AspNetRoles SET Name = 'SuperAdmin', NormalizedName = 'SUPERADMIN' WHERE Name = 'SuperDev';
UPDATE AspNetUserRoles
  SET RoleId = (SELECT Id FROM AspNetRoles WHERE Name = 'SuperAdmin')
  WHERE RoleId = (SELECT Id FROM AspNetRoles WHERE Name = 'SuperDev');

-- Remove obsolete roles
DELETE FROM AspNetUserRoles
  WHERE RoleId IN (SELECT Id FROM AspNetRoles WHERE Name IN ('ProctorReviewer', 'Auditor'));
DELETE FROM AspNetRoles WHERE Name IN ('ProctorReviewer', 'Auditor');
```

## Step 3 — Configure Backend (appsettings.json)

Edit `Backend\appsettings.json` with client-specific values:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=SmartExamDB;User Id=smartexam_user;Password=YourStrongPassword!;TrustServerCertificate=True;"
  },
  "EncryptionSettings": {
    "Key": "GENERATE_A_NEW_32_CHAR_RANDOM_KEY_HERE"
  },
  "JwtSettings": {
    "SecretKey": "GENERATE_A_STRONG_RANDOM_64_CHAR_JWT_SECRET_HERE",
    "Issuer": "SmartExam",
    "Audience": "SmartExamUsers",
    "AccessTokenExpirationHours": "1",
    "RefreshTokenExpirationHours": "20"
  },
  "AppSettings": {
    "BaseUrl": "https://exam.clientdomain.com",
    "SeedKey": "CHOOSE_A_STRONG_SEED_KEY_HERE"
  }
}
```

> ⚠️ **Security:** Never reuse the dev/test JWT secret or encryption key on the client server. Generate new ones.

**Generate a random key quickly (PowerShell):**

```powershell
# 64-char JWT secret
-join ((65..90 + 97..122 + 48..57) | Get-Random -Count 64 | ForEach-Object { [char]$_ })
```

## Step 4 — Deploy the License

### 4.1 Copy License Files to Server

Place the following files into `Backend\License\`:

```
Backend\License\
    license.json    ← generated by Build4IT for this client's domain
    public.pem      ← same for all clients (RSA public key)
```

### 4.2 Verify the License File

The `license.json` must match the client's domain/IP and have a valid expiry date.  
The backend validates this on every startup — if invalid, all API calls will return `403 License Invalid`.

> If the client's URL changes later (e.g., domain change), a new `license.json` must be generated and re-deployed.

## Step 5 — Deploy the Backend

### 5.1 Publish the Backend (on dev machine)

```bash
cd Backend-API
dotnet publish -c Release -o ./publish
```

### 5.2 Copy to Server

Copy contents of `./publish` to `C:\SmartExam\Backend\`

### 5.3 Configure IIS Application Pool

- Create a new Application Pool: `SmartExamPool`
- .NET CLR Version: **No Managed Code**
- Identity: **ApplicationPoolIdentity** (or a local service account)

### 5.4 Create IIS Website

- Site Name: `SmartExam API`
- Physical Path: `C:\SmartExam\Backend`
- Binding: Port `5221` (or 80/443 with domain)
- Application Pool: `SmartExamPool`

### 5.5 Set Folder Permissions

```powershell
icacls "C:\SmartExam\Backend" /grant "IIS_IUSRS:(OI)(CI)F"
icacls "C:\SmartExam\Backend\MediaStorage" /grant "IIS_IUSRS:(OI)(CI)F"
icacls "C:\SmartExam\Backend\Logs" /grant "IIS_IUSRS:(OI)(CI)F"
icacls "C:\SmartExam\Backend\License" /grant "IIS_IUSRS:(OI)(CI)R"
```

## Step 6 — Deploy the Frontend

### 6.1 Build the Frontend (on dev machine)

Update the API base URL in the frontend `.env.production`:

```env
NEXT_PUBLIC_API_URL=https://exam.clientdomain.com
```

Then build:

```bash
cd Frontend/Smart-Exam-App-main
pnpm build
```

### 6.2 Deploy Frontend

**Option A — Run as Next.js server (recommended):**

```bash
pnpm start
```

Use a process manager like PM2:

```bash
pm2 start "pnpm start" --name smartexam-frontend
pm2 save
pm2 startup
```

**Option B — Static Export (if applicable):**
Copy `out/` folder to IIS site root.

## Step 7 — Seed Initial Data (FIRST RUN ONLY)

After the backend is running, call the seed endpoint **once**:

```http
POST https://exam.clientdomain.com/api/Seed
X-Seed-Key: <your SeedKey from appsettings.json>
Content-Type: application/json
```

This will automatically create:

- ✅ All 6 roles: `SuperAdmin`, `Admin`, `Instructor`, `Candidate`, `Examiner`, `Proctor`
- ✅ SuperAdmin user:
  - **Email:** `super-admin@smartexam.local`
  - **Full Name:** System Administrator / مسؤول النظام
  - **Password:** `Smart@26Super5`

> **Do NOT call this endpoint again** — it is idempotent but should be protected after first use.

### 7.1 After Seeding — Secure the Seed Endpoint

In `appsettings.json`, change the `SeedKey` to a new value or remove it entirely to prevent re-seeding:

```json
"AppSettings": {
  "SeedKey": ""
}
```

## Security Reminders

- [ ] Change SuperAdmin password after first login
- [ ] Remove or blank the `SeedKey` after seeding
- [ ] Never store private.pem on the client server
- [ ] Keep `appsettings.json` permissions restricted — not publicly readable
- [ ] Enable HTTPS (SSL certificate) on IIS — do not run on HTTP in production
- [ ] Disable Swagger UI in production (or restrict by IP) — edit `Program.cs` or use IP filtering in IIS
- [ ] Schedule regular SQL Server backups
- [ ] Monitor `Backend\Logs\` for errors

## Troubleshooting

| Symptom                                  | Likely Cause                            | Fix                                                              |
| ---------------------------------------- | --------------------------------------- | ---------------------------------------------------------------- |
| API returns `403 License Invalid`        | license.json missing or domain mismatch | Re-check `License/` folder; regenerate license if domain changed |
| API returns `500` on startup             | Wrong DB connection string              | Check `appsettings.json` DefaultConnection                       |
| Seed endpoint returns `401 Unauthorized` | Wrong `X-Seed-Key` header               | Match exactly with `AppSettings.SeedKey` in appsettings          |
| Frontend shows blank page                | Wrong `NEXT_PUBLIC_API_URL`             | Rebuild frontend with correct env                                |
| Login fails for SuperAdmin               | Seed not run yet                        | Call `POST /api/Seed` first                                      |
| IIS returns `502.5`                      | .NET Hosting Bundle not installed       | Install ASP.NET Core Hosting Bundle                              |
| Files not uploading                      | MediaStorage folder permissions         | Run `icacls` command from Step 5.5                               |
