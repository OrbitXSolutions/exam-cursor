# D53 — Assessment authoring and question-source isolation

Classification: SIMULATED TEST through real API endpoints with independent persisted-state reads. All probes used freshly created disposable Engineering exams and existing QA bank questions; root lifecycle exam 123 and its attempt were not mutated.

Baseline `harness/phase9-assessment-before2.json`: 55 checks, 48 failed isolation expectations. Operations and no-department Admins could disable list isolation using FilterByUserDepartment=false, read nested sections/topics/questions/access codes/instructions/builder data, and inspect publication validation. An Operations Admin successfully created, edited, reordered, removed, toggled, unpublished and deleted Engineering resources. Direct exam detail correctly denied access, demonstrating the inconsistency. Several negative attempts happened to fail unrelated duplicate/order or publish validation and are not evidence of authorization enforcement.

The separate valid-input baseline `harness/d53-source-publication-before2.json` failed all three security checks: mixed allowed/foreign question selection persisted both rows; foreign Admin published an otherwise valid Engineering draft; Engineering Admin selected Operations' dynamic question pool. Another probe showed an Engineering Admin can move its exam into Operations: the write persists even though the resulting detail response denies access.

Minimal source fix: `Backend-API/Infrastructure/Services/Assessment/AssessmentService.cs`. List scope always enforces the current department unless SuperAdmin. Every previously unguarded nested reader/mutator resolves its parent exam and checks the existing department rule before cached reads or writes. Explicit question selections validate the complete requested set before mutation; random pools use the same scoped bank query. Builder sources validate subject scope and topic/subject membership before replacement. Exam movement also checks target-department access. SuperAdmin's existing global privileges remain. Publication invalidation matches the separately fixed scoped ExamProctor cache keys.

After restart7, the complete main matrix passed60/60 (`harness/phase9-assessment-after.json`) and the valid-source/publication extension passed3/3 (`harness/d53-source-publication-after.json`). Each foreign mutation checks both rejection and an independent unchanged privileged read. Positive coverage includes same-department single/bulk/manual selection with persisted point override, topic builder, sections/topics/instructions/access-policy authoring, publication/unpublication and cleanup. No-department reads and client filter-flag bypasses fail closed. Foreign bank single/bulk mixed sets and dynamic pools are denied before persistence. The DepartmentId transfer attempt is denied without changing the saved department.

Isolated backend build passed. The checkpoint suite passed234/skipped64/failed0; SQL/Redis fixture tests were deliberately skipped because their setup changes schema. This is API authorization/business-state evidence, not real-browser verification of every authoring control.
